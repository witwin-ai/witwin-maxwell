# Changelog

All notable user-visible changes to WiTwin Maxwell are documented here. The project follows semantic versioning within the `0.x` development series.

## [0.7.0] - 2026-11-14

Full details and migration notes are in the [0.7.0 release notes](docs/reference/release-notes-0.7.0.md).

### Breaking changes

- **`Scene` is immutable** (a frozen dataclass with identity equality and hashing). Its collections are tuples (`scene.structures`, `sources`, `monitors`, `ports`, `thin_wires`, `networks`, `lumped_elements`, `circuits`, `material_regions`, `electrostatic_terminals`, `charge_densities`, `internal_absorbers`); assigning a field or mutating a collection raises. The twelve `Scene.add_*` methods are removed (plan Q17: removed, not turned into functional variants) and `Scene.clone(**overrides)` is replaced by `Scene.updated(**fields)`, which returns a new `Scene`, shares every unchanged object and re-validates only the replaced fields and the cross-object rules that read them (ports against `structures`/`domain`, networks against `ports`, lumped elements and coordinates against `domain`). The constructor keeps its keywords and validation, so pass collections to it, or use `scene.updated(structures=(*scene.structures, s))`. `Scene.with_*` stays forbidden.

  | 0.6 | 0.7.0 |
  |---|---|
  | `scene.add_structure(s)` (likewise `add_source`, `add_monitor`, `add_port`, `add_thin_wire`, `add_lumped_element`, `add_network`, `add_circuit`, `add_material_region`, `add_internal_absorber`, `add_electrostatic_terminal`, `add_charge_density`) | `Scene(..., structures=(s, ...))` or `scene = scene.updated(structures=(*scene.structures, s))` |
  | `scene.clone(**overrides)` | `scene.updated(**fields)` |
  | `scene.structures[i] = s`, `scene.sources.clear()`, `scene.grid = g` | `scene = scene.updated(structures=..., sources=(), grid=g)` |
  | `Scene(subpixel_samples=...)` | `Scene(subpixel=...)` (a `SubpixelSpec`, or samples as before) |

- **`Scene(device=..., verbose=..., lazy_meshgrid=...)` are removed; the solver config owns device placement (plan Q18).** `FDTDConfig`, `FDFDConfig`, `mw.mom.MoMConfig`, `mw.electrostatic.ElectrostaticConfig` and `mw.electrostatic.CapacitanceConfig` gain `device` (default `"cuda"`; `MoMConfig.device` is placement only and does not enter its equality), and `FDTDConfig` gains `verbose` (`FDFDConfig.verbose` already existed). Preparation places the grid and compiled tensors on the config device; the declarative tensors of a scene are not copied. `lazy_meshgrid` is an internal preparation option. A non-CUDA device is refused with `requires config.device to be CUDA` (previously `requires scene.device to be CUDA`). `prepare_scene(scene, device=...)` and `compile_electrostatics(scene, ..., device=...)` take the device (default CUDA), `Result.load(..., device="cuda")` names the device of restored MoM state, and `import_pcb_scene(...)` and `ProcessStack.scene_from_gds(...)` drop their `device` argument. Migration: move `device=`/`verbose=` from `Scene(...)` to the config (`mw.FDTDConfig(device="cuda:1")`); scene-only CPU work passes `device="cpu"` to `prepare_scene` or the compile call.
- `mw.rf.PECFrame(length).structures(port, scene, device=...)` takes the device explicitly (no default): a declarative `scene` is prepared there, so it must be where the scene's geometry tensors live (pass `prepared.device` with a prepared scene). Before this fix 0.7.0 prepared it on the host, which failed for CUDA-resident geometry touching the PML; WavePort and TerminalWavePort runs now lay out their injection planes on `config.device` as in 0.6.
- **Legacy `Scene` convenience properties are removed:** `bc_type`, `boundary_type` (use `scene.boundary.kind`), `pml_thickness`, `pml_strength` (use `scene.boundary.num_layers`/`strength`), `dx`/`dy`/`dz`, `grid_spacing` (use `scene.grid.dx`/`spacing`), `domain_size`, `bloch_wavevector`, `bloch_phase_factors` (use `scene.boundary`), `subpixel_samples` (use `scene.subpixel.samples`) and `physical_positions` (use `scene.coordinates.position(...)`). `boundary_face_kind`, `pml_thickness_for_face`, `has_symmetry`, `resolved_sources()`, `resolved_monitors()`, `to_dict()` and `from_dict()` stay.
- **`Scene.to_tidy3d(...)` is removed (plan phase 7c).** Export through the adapter function `witwin.maxwell.adapters.tidy3d.scene_to_tidy3d(scene, frequencies=..., run_time=..., **kwargs)`, which the method only delegated to (it also takes `length_scale` and `cw_steady_state`); the exported simulation is unchanged. Adapter error messages now name `scene_to_tidy3d()`. Migration: `scene.to_tidy3d(...)` becomes `scene_to_tidy3d(scene, ...)`.
- Without a solver config, grid layout follows the data: `Result.prepared_scene`, `Result.fields` and the postprocessing that reads them (power loss, raw monitors, closed-surface payloads) lay out the grid on the device of the stored result tensors, or on the host when the result holds none; material pullbacks run on the device of the adjoint gradients. `FDTDConfig.verbose` is a fixed input (a trainable tensor is refused like the other execution flags).
- `SceneModule.to_scene()` is unchanged. Building the static part once (`self._base = mw.Scene(...)`) and returning `self._base.updated(material_regions=(...))` shares every static object, and the static parts are not recompiled (see Added).
- Migration for the whole phase: `python scripts/dev/codemods/070_p7a_scene_frozen.py apply <paths>`, then `check`. It folds `scene.add_*` sequences into the constructor, rewrites the remaining additions, `clone`, field and item assignments to `updated`, moves dropped constructor keywords, and lists what it cannot decide (additions to function parameters or free names, simulation-scene mutations, reads of removed members).

- **`Scene.compile_*` and the `PreparedScene` compile methods are internal functions of `witwin.maxwell.compiler`** that take the prepared scene first; `PreparedScene` is no longer a `Scene` subclass. A `PreparedScene` (from `witwin.maxwell.scene.prepare_scene(scene, device=...)`) holds the grid state, the compile caches and `prepared.scene`, the prepared declarations (the scene with the resolved grid, the PML extrusions and the coordinates on the device); read declarations there (`prepared.scene.structures`), not on the prepared scene. `witwin.maxwell.compiler` is internal and in no public `__all__`. No numerical change.

  | 0.7.0 phase 7a | 0.7.0 |
  |---|---|
  | `scene.compile_ports(device=d)` (likewise `compile_thin_wires`, `compile_wire_monitors`, `compile_waveports`, `compile_lumped_elements`, `compile_networks(dt=...)`, `compile_circuits`) | `compile_ports(prepare_scene(scene, device=d))` |
  | `prepared.compile_materials(subpixel_samples=s)` (likewise `compile_material_components`, `compile_relative_materials`, `compile_material_tensors`, `compile_mass_density`, `compile_gyromagnetic_materials`, and the port/wire/network/lumped/circuit compiles) | `compile_materials(prepared, subpixel=s)` |
  | `scene.compile_array_monitors(...)`, `scene.compile_electrostatics(...)` | `compile_array_monitors(scene, ...)`, `compile_electrostatics(scene, ...)` (from `witwin.maxwell.compiler.electrostatic`) |
  | `prepared.structures`, `prepared.boundary`, `prepared.resolved_sources()` (any `Scene` field or method on a `PreparedScene`) | `prepared.scene.structures`, `prepared.scene.boundary`, `prepared.scene.resolved_sources()` |

  Migration: `python scripts/dev/codemods/070_p7b_compiler_internal.py apply <paths>`, then `check`. It rewrites the compile method calls and adds the imports; reads of `Scene` fields on a `PreparedScene` are not rewritten (they raise `AttributeError`).

- **`fdtd_core_path` and `accelerated_setup` are removed from `Simulation.fdtd(...)` and `FDTDConfig`.** The accelerated CUDA path is the only public FDTD path: every eligible scene runs on the core path with accelerated setup, as under the 0.6.0 `"auto"` default. Passing either keyword now raises `TypeError` (unexpected keyword argument). Since W7 row 16c every FDTD scene runs on the core path and nothing falls back to the existing stepping path (see the next entry); the 0.6.0 explicit-`True` continuation of a failed whole-step capture on the per-step core loop is gone.

  | 0.6.0 | 0.7.0 |
  |---|---|
  | `fdtd_core_path="auto"`, `accelerated_setup="auto"` (defaults) | remove the keywords; same behavior |
  | `fdtd_core_path=True` (refuse ineligible scenes with `ValueError`) | remove the keyword; every scene runs on the core path |
  | `fdtd_core_path=False` and/or `accelerated_setup=False` (existing path, PyTorch setup) | no replacement; the existing path is internal |
  | `accelerated_setup=True` | remove the keyword; setup acceleration is automatic |
  | `FDTDConfig.fdtd_core_path`, `FDTDConfig.accelerated_setup` | removed attributes |

- **`mw.fdtd.FDTDCoreFallbackWarning` and the `execution_path`/`fallback_reason` keys of `Result.stats()` and `Result.metadata` are removed; a failed core attempt raises instead of falling back (W7 row 16c, user decision 2026-11-12).** No admission blocker is left, so the automatic fallback to the existing stepping path is gone and there is no deprecation shim. A failure of the accelerated CUDA setup retries the preparation once on the core path with the PyTorch setup (the numerics of a material-cache run) and warns with `mw.MaxwellWarning`; a second failure raises. A failure to load the core-path library, to activate the core path, or to capture or replay the whole-step CUDA graph raises that error (the solver state is restored first; a fresh `prepare()` starts over). The same holds for the differentiable forward and for multi-GPU shards, which no longer rebuild bounded per-component kernels after a failed core activation. `ESDCurrentSource` scenes, which kept the existing path through the `"unsupported source type"` blocker, run on the core path (the source lowers to a `UniformCurrentSource`; results are bitwise unchanged). A wheel build with only some of the three prebuilt FDTD libraries is refused. Features no path supports still raise their own refusals, and a CPU scene still raises `ValueError` at preparation.

  | 0.6.0 / earlier 0.7.0 | 0.7.0 |
  |---|---|
  | `warnings.simplefilter("error", mw.fdtd.FDTDCoreFallbackWarning)` | remove the filter; failures raise |
  | `result.stats()["execution_path"]`, `result.metadata["execution_path"]` | removed (always the core path) |
  | `result.stats()["fallback_reason"]`, `result.metadata["fallback_reason"]` | removed; a failure raises its own exception |
  | a failed core activation, capture or library load rebuilt the run on the existing path | the error propagates |
  | a failed accelerated setup rebuilt the run on the existing path with PyTorch setup | the run retries on the core path with PyTorch setup and warns (`mw.MaxwellWarning`) |

- **The CPU reference FDTD profile and the kernel-selector environment variables are removed.** FDTD runs on CUDA only. `Simulation.fdtd(..., backend=...)` and `FDTDConfig.backend` are deleted (passing `backend` raises `TypeError`), and a CPU scene is refused by the existing CUDA requirement (`ValueError`). `WITWIN_MAXWELL_THIN_SHEET_KERNEL` and `WITWIN_MAXWELL_COPPER_KERNEL` are no longer read: conformal thin sheets and ordinary `CopperFoil` sheets always run their fused CUDA kernels (paired, phase and material-trace ADE foils keep their Torch copper step, as before). No CUDA result changes. Reference implementations that no production path ran moved out of the package into the test suite (`tests/oracles/`): the Torch Yee kernel subset of the CPU profile, the Torch thin-sheet arithmetic, `fdtd.ferrite_reference`, `fdtd.surface_impedance_reference`, `fdtd.thin_wire_reference`, `fdtd.curved_copper`, `compiler.curved_copper`, `compiler.nonlinear_devices` (with `NonlinearDeviceError` and `NonlinearConvergenceError`) and the pure gyromagnetic recurrence `fdtd.runtime.advance_gyromagnetic_state`/`apply_gyromagnetic_correction`. `fdtd.evaluation` (CPML tuning helpers) is deleted, and the distributed step-rate instrument `fdtd.distributed.instrumentation` moved to the test support code.

  | 0.6.0 | 0.7.0 |
  |---|---|
  | `Simulation.fdtd(..., backend="native")` | remove the keyword; same behavior |
  | `Simulation.fdtd(cpu_scene, backend="cpu_reference")` | no replacement; run the scene on CUDA |
  | `WITWIN_MAXWELL_THIN_SHEET_KERNEL=torch`, `WITWIN_MAXWELL_COPPER_KERNEL=torch` | no replacement; the variables are ignored |
  | `witwin.maxwell.fdtd.ferrite_reference`, `.surface_impedance_reference`, `.thin_wire_reference`, `.curved_copper`, `.evaluation`, `.distributed.instrumentation`; `witwin.maxwell.compiler.curved_copper`, `.nonlinear_devices` | removed modules |

- **`FDTDConfig`, `FDFDConfig` and `SpectralSampler` are frozen dataclasses.** Assigning to a field raises `dataclasses.FrozenInstanceError`. Previously the assignment succeeded and skipped the constructor's validation and normalization (for example `config.run_time = None` was accepted). Build a new record with `dataclasses.replace(...)`, which validates it again. `TimeConfig`, `GMRES` (now `FDFDSolverConfig`) and `MoMConfig` were already frozen.

  | 0.6.0 | 0.7.0 |
  |---|---|
  | `simulation.config.run_time = mw.TimeConfig(time_steps=n)` | `simulation.config = dataclasses.replace(simulation.config, run_time=mw.TimeConfig(time_steps=n))` |
  | `simulation.config.spectral_sampler.window = "none"` | `simulation.config = dataclasses.replace(simulation.config, spectral_sampler=dataclasses.replace(simulation.config.spectral_sampler, window="none"))` |
  | `simulation.config.local_response = ...` (FDFD) | `simulation.config = dataclasses.replace(simulation.config, local_response=...)` |

- **`Simulation(...)` no longer takes `reference_frequency=` or `material_cache=`, and the `Simulation.material_cache` attribute is removed.** Both settings live only in `FDTDConfig`; the new field `FDTDConfig.material_cache` holds the `FDTDMaterialCache`. `FDTDConfig(reference_frequency=..., material_cache=...)` sets them (the `Simulation.fdtd(...)` keywords of the same name moved into `config=`, see the single configuration entry below). `FDTDConfig(material_cache=...)` raises `TypeError` for a value that is not an `FDTDMaterialCache` (previously raised by `Simulation(...)`). FDFD and MoM simulations have no such fields; the former `ValueError`/`TypeError` for passing them to a non-FDTD `Simulation(...)` is gone with the keywords.

  | 0.6.0 | 0.7.0 |
  |---|---|
  | `mw.Simulation(..., config=cfg, reference_frequency=f)` | `mw.Simulation(..., config=dataclasses.replace(cfg, reference_frequency=f))` |
  | `mw.Simulation(..., config=cfg, material_cache=cache)` | `mw.Simulation(..., config=dataclasses.replace(cfg, material_cache=cache))` |
  | `simulation.material_cache` | `simulation.config.material_cache` |

- **`FDTDConfig.cpml_config` (a dict) is replaced by `FDTDConfig.cpml`, a frozen `CPMLConfig` dataclass; the dict form is removed.** `Simulation.fdtd(..., cpml_config=...)` becomes `FDTDConfig(cpml=mw.fdtd.CPMLConfig(...))` (passed as `Simulation.fdtd(..., config=...)`, see the single configuration entry below). A misspelled key such as `{"kapa_max": 5.0}` was previously ignored; an unknown field is now a `TypeError` from the dataclass constructor, and passing a dict to `FDTDConfig(cpml=...)` raises `SetupError`. `memory_mode` is the new `str` Enum `CPMLMemoryMode` (`AUTO`, `DENSE`, `SLAB`); the exact strings `"auto"`, `"dense"` and `"slab"` are still accepted and parsed, while other spellings (`"Dense"`, `" slab "`), previously normalized, raise `SetupError`. Out-of-range values (`kappa_max < 1`, negative `alpha_max` or `dense_memory_limit_mib`, `reflection` outside (0, 1), nonpositive `grading_order`, non-finite numbers) raise `SetupError` at construction. `grading_order`, `alpha_max` and `reflection` default to `None` (the solver default: 3, 0 and 1e-6, or the shifted complex fixed-k profile), replacing the "was the key passed" rule; values and fields are unchanged. `witwin.maxwell.fdtd.DEFAULT_CPML_CONFIG` is removed (`mw.fdtd.CPMLConfig()` holds the defaults), and the prepared solver's `cpml_config` dict is replaced by `solver.cpml` (the configuration) and `solver.cpml_grading` (the resolved profile).

  | 0.6.0 | 0.7.0 |
  |---|---|
  | `Simulation.fdtd(..., cpml_config={"memory_mode": "slab"})` | `Simulation.fdtd(..., config=mw.FDTDConfig(cpml=mw.fdtd.CPMLConfig(memory_mode=mw.fdtd.CPMLMemoryMode.SLAB)))` (or `memory_mode="slab"`) |
  | `cpml_config={"alpha_max": 0.0, "kappa_max": 5.0}` | `cpml=mw.fdtd.CPMLConfig(alpha_max=0.0, kappa_max=5.0)` |
  | `FDTDConfig(cpml_config={...})`, `config.cpml_config` | `FDTDConfig(cpml=mw.fdtd.CPMLConfig(...))`, `config.cpml` |
  | `witwin.maxwell.fdtd.DEFAULT_CPML_CONFIG` | `mw.fdtd.CPMLConfig()` |
  | `prepared.solver.cpml_config["alpha_max"]` (resolved value) | `prepared.solver.cpml_grading.alpha_max` |
  | `cpml_config={"memory_mode": "Dense"}` (normalized) | `memory_mode="dense"` or `CPMLMemoryMode.DENSE` |

- **`Simulation.fdtd(...)` and `Simulation.fdfd(...)` take one configuration entry.** The signatures are `Simulation.fdtd(scene, *, frequencies, excitations=None, config=None)` and `Simulation.fdfd(scene, *, frequencies, config=None)`; `config` is an `FDTDConfig` / `FDFDConfig` (`None` means the defaults). Every other keyword argument of the factories is removed and is now the config field of the same name, with the same meaning and default; passing one to the factory raises `TypeError` (unexpected keyword argument). `frequency=` is removed (one entry, no alias): `frequencies` is required and takes one frequency or a sequence. The old factories turned `run_time=None`, `spectral_sampler=None`, `cpml=None` and `solver=None` into the defaults; the config fields take a value, so omit the field instead (`FDTDConfig(run_time=None)` raises `TypeError`). Numerics and every default are unchanged. `Simulation.mom(...)` follows the same frequency rule: its signature is `Simulation.mom(scene, *, frequencies=None, config=None)`, `frequency=` is removed, and `frequencies` takes one frequency or a sequence (it stays omitted for an adaptive layered sweep, `LayeredSurfaceConfig.sweep`, which defines its own frequencies). `Simulation.electrostatic(...)` and `Simulation.capacitance(...)` are unchanged here. The rewrite of in-repo call sites is `scripts/dev/codemods/070_p4c_single_entry.py` (`apply`, then `check`); it also serves as the migration aid for downstream code.

  | 0.6.0 | 0.7.0 |
  |---|---|
  | `Simulation.fdtd(scene, frequency=f, ...)`, `Simulation.fdfd(scene, frequency=f, ...)` | `Simulation.fdtd(scene, frequencies=f, ...)`, `Simulation.fdfd(scene, frequencies=f, ...)` |
  | `Simulation.mom(scene, frequency=f, config=c)` | `Simulation.mom(scene, frequencies=f, config=c)` |
  | `Simulation.fdtd(scene, frequencies=fs, run_time=t, spectral_sampler=s, full_field_dft=b, cuda_graph=g)` | `Simulation.fdtd(scene, frequencies=fs, config=mw.FDTDConfig(run_time=t, spectral_sampler=s, full_field_dft=b, cuda_graph=g))` |
  | `Simulation.fdtd(..., absorber=, reference_frequency=, cpml=, enable_plot=, field_dtype=, shutoff=, shutoff_check_interval=, parallel=, initial_condition=, material_cache=)` | the `FDTDConfig` field of the same name |
  | `Simulation.fdtd(..., excitations=e, run_time=t)` | `Simulation.fdtd(..., excitations=e, config=mw.FDTDConfig(run_time=t))` (`excitations` stays a factory keyword) |
  | `sim = Simulation.fdtd(...)`; `sim.config = replace(sim.config, adjoint_checkpoint_stride=k)` | `Simulation.fdtd(..., config=mw.FDTDConfig(adjoint_checkpoint_stride=k))` (the field was not a factory keyword) |
  | `Simulation.fdfd(..., solver=s, enable_plot=, verbose=, local_response=, observations=)` | `Simulation.fdfd(..., config=mw.FDFDConfig(solver=s, ...))` |
  | `Simulation.fdtd(..., run_time=None)`, `spectral_sampler=None`, `cpml=None`, `Simulation.fdfd(..., solver=None)` | omit the field |
  | `kwargs = dict(frequency=f, run_time=t)`; `Simulation.fdtd(scene, **kwargs)` | `Simulation.fdtd(scene, frequencies=f, config=mw.FDTDConfig(run_time=t))`; a forwarded mapping holds either config fields (`config=mw.FDTDConfig(**kwargs)`) or the entry keywords `frequencies`/`excitations`/`config` |

- **`GMRES` is renamed `FDFDSolverConfig`.** It configures every FDFD linear solve, not only GMRES: `solver_type` selects `"gmres"`, `"cg"`, `"bicgstab"`, `"tfqmr"`, `"idr"`, `"sqmr"` or `"direct"`. Fields, defaults and validation are unchanged; `FDFDConfig.solver` holds an `FDFDSolverConfig`, and a non-`FDFDSolverConfig` value raises `TypeError`. There is no `mw.GMRES` alias.

  | 0.6.0 | 0.7.0 |
  |---|---|
  | `mw.GMRES(max_iter=200, solver_type="direct", ...)` | `mw.fdfd.FDFDSolverConfig(max_iter=200, solver_type="direct", ...)` |
  | `from witwin.maxwell import GMRES` | `from witwin.maxwell import FDFDSolverConfig` |
  | `Simulation.fdfd(scene, frequency=f, solver=mw.GMRES(...))` | `Simulation.fdfd(scene, frequencies=f, config=mw.FDFDConfig(solver=mw.fdfd.FDFDSolverConfig(...)))` |

- **`Simulation.electrostatic(...)` and `Simulation.capacitance(...)` return a `Simulation` and take one configuration entry.** The signatures are `Simulation.electrostatic(scene, *, config=None)` and `Simulation.capacitance(scene, *, config=None)`; every other keyword is a field of the new frozen dataclasses `ElectrostaticConfig(boundary, solver)` and `CapacitanceConfig(terminals, reference, boundary, solver, truncation_estimate)` (exported as `mw.electrostatic.ElectrostaticConfig`, `mw.electrostatic.CapacitanceConfig` and from `mw.electrostatic`; `dataclasses.replace` re-validates). The runner classes `ElectrostaticSimulation` and `CapacitanceSimulation` are removed. Static simulations have `method` `SimulationMethod.ELECTROSTATIC`/`CAPACITANCE` (new members), no frequencies (`frequencies == ()`, `frequency is None`), `Simulation.check()` reports them against the electrostatic/capacitance capability tables, construction/`prepare()`/`run()` raise the refused items, and a `SceneModule` scene is accepted. `prepare()` returns a `PreparedSimulation` whose `solver` is the compiled electrostatic block (previously `prepare()` returned that block). Results are bitwise unchanged. A `CapacitanceConfig` with a `truncation_estimate` and no Dirichlet face raises `ValueError` at construction (previously after the base extraction in `run()`). A non-`none` `Scene.boundary` face is refused at construction and reported by `check()` (previously admitted there and refused by the compile step in `prepare()`/`run()`). Migration: `python scripts/dev/codemods/070_p4d_es_config.py apply <paths>`.

  | 0.6.0 | 0.7.0 |
  |---|---|
  | `Simulation.electrostatic(scene, boundary=b, solver=s)` | `Simulation.electrostatic(scene, config=mw.electrostatic.ElectrostaticConfig(boundary=b, solver=s))` |
  | `Simulation.capacitance(scene, terminals=t, reference=r, boundary=b, solver=s, truncation_estimate=e)` | `Simulation.capacitance(scene, config=mw.electrostatic.CapacitanceConfig(terminals=t, reference=r, boundary=b, solver=s, truncation_estimate=e))` |
  | `boundary=None`, `solver=None` | omit the field (defaults: `ElectrostaticBoundarySpec.grounded_box()`, `ElectrostaticSolverConfig()`) |
  | `Simulation.electrostatic(scene).prepare()` (a `CompiledElectrostatics`) | `Simulation.electrostatic(scene).prepare().solver` |
  | `runner.boundary`, `runner.solver`, `runner.terminals`, `runner.reference`, `runner.truncation_estimate` | `simulation.config.boundary`, `.solver`, `.terminals`, `.reference`, `.truncation_estimate` |
  | `isinstance(x, mw.electrostatic.ElectrostaticSimulation)` / `CapacitanceSimulation` | `isinstance(x, mw.Simulation) and x.method is mw.SimulationMethod.ELECTROSTATIC` / `CAPACITANCE` |
  | `Simulation(scene=..., method="electrostatic", ...)` was not available | `mw.Simulation(scene=s, method="electrostatic", frequencies=(), config=mw.electrostatic.ElectrostaticConfig())` |

- **Invalid electrostatic configuration values raise `SetupError`** (a `ValueError`, so `except ValueError` keeps working), as `CPMLConfig` and the Enum options do: `ElectrostaticSolverConfig` (`tolerance <= 0`, `max_iterations <= 0`, a dtype other than float32/float64), `TruncationEstimate(padding_cells <= 0)`, `ElectrostaticBoundarySpec` (an unknown boundary kind, an override that is neither a kind nor a `(kind, value)` pair, a non-zero value on a non-Dirichlet face) and `CapacitanceConfig(truncation_estimate=...)` without a Dirichlet face. Messages are unchanged.

- **Wave-port, terminal wave-port and modal-port sweeps, and a direct `WavePort` excitation, refuse a configured `FDTDConfig.material_cache`.** These runners build one simulation per column and never applied the cache, so the setting was silently ignored. They now raise `UnsupportedFeatureError` (`method="fdtd"`) before running any column. Migration: leave `material_cache` unset for these runs; lumped-port `PortSweep` runs still use the cache.

- Homogeneous (non-layered) `Simulation.mom(...)` refuses, at construction and in one `NotImplementedError` listing every item, scene declarations it previously ignored: `Material(pmc=True)` bodies (previously solved as vacuum), non-default core `PhysicalMaterial` surface-model fields (`dispersion`, `conductor_model`, `thickness_m`, `layers`, `geometry_mode`, roughness, gain, scattering/xpd), `Scene.internal_absorbers`, `PlaneWave(injection=TFSF(...))` and `injection_axis`, and trainable `mu_r` or `MaxwellPlaneModes` tensors (previously solved with their gradients detached). Migration: remove the declaration, or use `Simulation.fdtd(...)` for grid features.
- `Simulation.electrostatic(...)`, `Simulation.capacitance(...)` and `Scene.compile_electrostatics()` refuse, in one listing `NotImplementedError`, declarations the static solve previously ignored: sources, monitors, ports, lumped elements, networks, circuits, thin wires, internal absorbers, `Scene.symmetry`, `Scene.coordinates`, `LossyMetalMedium`/`SurfaceImpedanceMedium`/`CopperFoil`/`Medium2D` structures (previously solved as vacuum), `sigma_e`/`sigma_e_tensor`, non-default core surface-model fields and trainable terminal geometry. Capacitance extraction also refuses floating (`charge=`) terminals (previously grounded at 0 V) and `Scene.charge_densities` (previously ignored). Migration: a conductor must be an `ElectrostaticTerminal`; solve floating conductors and free charge with `Simulation.electrostatic(...)`; use `ElectrostaticBoundarySpec` symmetry faces instead of `Scene.symmetry`.

- **`Scene.symmetry` scenes reproduce their explicit mirrored domain.** A folded scene stands for the kept part plus its mirror images, and three quantities were computed over the folded domain instead:
  - a soft `PlaneWave` was normalized to unit power over the folded aperture, which also drops the absorber cells on the folded face, so its field was too large by `sqrt(2)` per folded axis against the mirrored domain (and by `sqrt((N + 2L)/(N + L))` against the same bounds without symmetry). It is now normalized over the mirrored-domain aperture: the folded run equals the unfolded run on the kept part (bitwise on the tested uniform grids), and a unit plane wave carries one watt in the mirrored domain;
  - a `GaussianBeam`/`AstigmaticGaussianBeam` took its launch-plane reference delay at the center of the folded plane, a global time shift (about 90 degrees at the carrier on a quarter domain); it now uses the mirrored-domain center;
  - domain-spanning plane flux (`FluxMonitor`, flux-enabled `PlaneMonitor`, `IncidentPowerDensityMonitor` flux, `FluxTimeMonitor`) integrated the kept part only. It now reports the mirrored-domain power, twice the kept integral per folded axis tangential to the plane (the raw payload lists the image-plane axes in `symmetry_image_planes`). A flux-enabled `FinitePlaneMonitor` symmetric about an image plane counts twice per plane, one on the kept side once, and one crossing an image plane asymmetrically is refused at construction (`symmetry.finite_plane_image_plane`).

  - a `ModeSource`, `ModeMonitor`, `ModePort`, `WavePort` or `TerminalWavePort` whose mode plane touches an image plane was solved on the folded aperture with a zero-field edge at the plane and normalized to unit power there: under a PEC plane the effective index was off by 0.6 % and the mirrored domain carried 2 W; under a PMC plane the solver returned a different mode. Such mode planes are now refused at construction (`symmetry.mode_plane_image_plane`); keep the mode plane more than half a cell from every image plane or simulate the full domain. PEC/PMC-aware transverse mode operators are a follow-up.

  Behavior change for every symmetry scene with a soft plane wave or a Gaussian beam: fields fall by `1/sqrt(2)` per folded axis (plane wave) or change phase (beam). Plane-wave flux totals are unchanged (the two corrections cancel); flux of other sources under symmetry doubles per folded tangential axis. The reference-solver export of a face-symmetric scene is now its mirrored domain with center symmetry planes (structures and regions must be boxes symmetric about the image plane there). Benchmark rows `symmetry_center`, `symmetry_pec_center` and `symmetry_pmc_center` are now defined as the kept part of the scene their reference describes.

- **`Scene.from_dict(scene.to_dict())` rebuilds every geometry tensor bit for bit, dtype included.** In 0.6 geometry fields (Box/Sphere/... position, size, radius, rotation, boolean smoothness, PolySlab/PlanarPEC/SurfaceMesh vertices, Mesh vertices and faces, and geometry nested in ports such as `LumpedPort`/`TerminalPort` `current_surface` and `voltage_aperture`) were written as bare JSON lists and rebuilt as float32, so float64 geometry drifted by about 1e-8 relative on the first save/load, int32 Mesh faces came back int64, and a scene whose float32-rounded port aperture failed validation (benchmark `printed_dipole_scene`) could not be rebuilt at all. `witwin.scene/2` keeps every tensor dtype (see Breaking changes); a 0.6 document is read through `mw.io.migrate_scene_dict`, which reads a bare geometry value float32 cannot represent as float64 (the old writers stored full-precision values) and every other bare value as before. `geometry.ComplexPolySlab`, on which 0.6 raised `AttributeError`, is serialized.

- A resumed FDTD run on the existing runner (scenes a blocker keeps off the core path) with embedded-network or terminal ports reports the same port and network voltage, current and power as its uninterrupted run. Its embedded-terminal observer graph read the port DFT rows from step 0 after the resume, so those spectra were wrong (up to 89 % of the peak on a one-port network fixture). Fields were unaffected.

- Thin-wire ports bound with `WirePortBinding.nodes(...)` converge under grid refinement. The port voltage was the difference of the terminal node potentials `q/C_node` alone; that potential carries only the wire's quasi-static self term, so the Yee field between the two terminals was missing from the port voltage and drive, which left a grid-dependent series reactance (input reactance and S11 diverged under refinement, 0.6.0 known limitation). The node binding now adds the conservative Yee line integral along the straight chord between its terminals, sampled exactly like a removed feed gap: a node-bound feed between two arm ends is the same port model as the `gap` binding of the joined wire, and a node binding across a physical wire segment reads that segment's EMF. Results of every scene with a node-bound port change (intended); gap-bound ports and wires without ports are unchanged (`torch.equal` compiled networks). Known limitation that remains (it applies equally to the `gap` binding): R converges; X carries a placement-dependent bias. Input resistance matches a qualified thin-wire integral-equation reference within a few percent, while the input reactance of short and near-resonant dipoles depends on where the wire runs in the Yee cell (up to about 15-25 % high in |X| on or near a grid node line, within about 5 % in mid-cell or oblique runs).

- **Dispersive media under `SubpixelSpec(averaging="polarized")`, `"polarized_tensor"` and `"kottke_smooth"` now follow the interface rule of the static medium.** Interface Yee edges blended the high-frequency permittivity with the window rule (normal projection or Kottke window) but scaled the Debye/Lorentz/Sellmeier pole strengths by the node volume fraction, averaged node to edge, so the dispersive part of the medium was blended arithmetically and curved dispersive interfaces did not converge (a Sellmeier sphere stalled near 3.3% extinction error against Mie; with the fix 1.2% at the same grid). Each pole weight is now the edge-native volume fraction scaled so the edge reproduces the window rule exactly in the static and high-frequency limits (pole frequencies keep their bulk values; Drude poles keep the edge volume fraction). Results of every such scene with partially filled dispersive cells change; bulk cells, the default `kottke_edge` and `arithmetic` are unchanged.

- FDTD differentiates a trainable `MaterialRegion` geometry (for example its position) through the gradient bridge. It was missing from the trainable census, so the run went forward-only and returned outputs detached from it. Forward values are unchanged. Batch and multi-GPU runs refuse it, as they refuse other trainable geometry (multi-GPU previously ran it forward-only).

- Multi-frequency FDFD Results and local-response Results (`prepare().run()`, `trial(...).result()`, `accept(...)`) keep `Simulation.metadata`, as single-frequency `run()` does; they previously returned an empty `Result.metadata`.

- FDFD differentiates a trainable `Material(sigma_e=<tensor>)` at exactly 0: the conductivity was folded into the complex permittivity only when nonzero, so its gradient came back as zero. Forward values are unchanged. A SceneModule FDFD run under `torch.no_grad()` now runs the detached solve; it previously raised `NotImplementedError` from the gradient bridge.

- Differentiable `Simulation.batch(...)` lanes now return `Result.embedded_networks` / `Result.embedded_network(name)`, bound to the adjoint port outputs, and their `PortData`, `CircuitData` and `EmbeddedNetworkData` tensors keep the autograd graph. Differentiable lanes previously returned no embedded networks and exported port and circuit records detached, so objectives built from them silently had no gradient.

- Electrostatics and capacitance are differentiable in a trainable isotropic `Material(eps_r=<tensor>)`, as the capacitance docstring states. The permittivity was converted to a float and the result was detached; forward values are unchanged (`torch.equal`). Under an anisotropic (tensor) dielectric such a permittivity now fails closed instead of being detached.

- Identical FDTD runs with CPML boundaries are bitwise repeatable regardless of what other processes hold on the GPU. The default `"auto"` CPML memory mode chose dense or slab `psi` storage from the card's free memory at prepare time, and the two layouts round differently, so a scene whose dense storage is at most 64 MiB gave different bits whenever the card had less than eight times that storage free (at most 512 MiB). The choice now depends only on the scene (see Changed).

- Layered MoM vertical Green tables over a stack PEC ground (for example a microstrip with vertical edge ports at 1 GHz and above) were refused by the z/rho interpolation admission even though they were accurate: rows whose source or observer lies on the PEC plane hold a horizontal kernel that cancels against its image to denormal noise, and the horizontal admission divided by that row's own magnitude. Horizontal admission rows now use the vertical rule, a floor of 1e-6 times the per-frequency family maximum. Table values are unchanged; only the admission verdict changes.

- Layered MoM horizontal Green tables with a plane on a stack PEC ground and further planes above it (for example the planes {0, 100, 110} um of a PEC / 100 um / 10 um via stack, needed by grounded vertical ports in multi-plane stacks) were refused by their own interpolation admission (6e4 at 1 GHz) although every row interpolates to about 1e-8: a tangential row with one end on the PEC plane cancels against its image to roundoff and was normalized only by its own maximum. The admission now floors every row at 1e-6 of the maximum over all plane pairs of its frequency and component. Table values are unchanged (every tensor of 12 previously admitted tables is bitwise identical); the admission verdict can only decrease.

### Breaking changes

- **The surface-integral solver is renamed from SIE to MoM.** The old names are removed; there are no deprecated aliases.

  | 0.5.1 | 0.6.0 |
  |---|---|
  | `Simulation.sie(...)` | `Simulation.mom(...)` |
  | `SimulationMethod.SIE` (value `"sie"`) | `SimulationMethod.MOM` (value `"mom"`) |
  | `SIEConfig` | `MoMConfig` |
  | `SIEPeriodicConfig` | `MoMPeriodicConfig` |
  | `SIEDyadicPeriodicConfig` | `MoMDyadicPeriodicConfig` |
  | `witwin.maxwell.sie.*` (including `SIERuntime`) | `witwin.maxwell.mom.*` (`MoMRuntime`) |
  | `Result.method == "sie"` | `Result.method == "mom"` |
  | native op namespace `witwin_maxwell_sie_layered` | `witwin_maxwell_mom_layered` |
  | `WITWIN_MAXWELL_SIE_LAYERED_BUILD_DIR` | `WITWIN_MAXWELL_MOM_LAYERED_BUILD_DIR` |
  | periodic payload ids `sie_bravais_ewald_config_v1`, `sie_bravais_dyadic_config_v1` | `mom_bravais_ewald_config_v1`, `mom_bravais_dyadic_config_v1`; periodic results saved under the old ids do not restore |

  - Result snapshots and metadata written with the old method name, layered ABI tag or other renamed schema strings are not restored. The surface-integral formulation identifiers (`pmchwt_scalar_sie`, `anisotropic_dgf_sie`, `coupled_sie_vie_*`) are unchanged.
  - Downstream consumers importing `witwin.maxwell.sie` must move to `witwin.maxwell.mom`.

### Changed (defaults and behavior; recompute affected cached results)

- **FDTD execution defaults to `fdtd_core_path="auto"` and `accelerated_setup="auto"`.** In 0.5.1 both were off.
  - Eligible single-GPU float32 forward scenes now run on the fused CUDA core path, with CUDA material and coefficient setup.
  - Scenes with an admission blocker keep the existing stepping. So do resume, non-initializing preparation and material-cache runs. The first automatic fallback in a `Simulation` warns once with the public `FDTDCoreFallbackWarning`.
  - If core activation or graph capture fails under `"auto"`, the run is rebuilt on the existing path.
  - `Result.stats` and `Result.metadata` report `execution_path` (`"core"` or `"existing"`) and `fallback_reason`.
  - Explicit `True` stays fail-closed: it raises for an ineligible scene. Explicit `False` keeps the existing path and does not warn.
  - PMC boundaries keep the existing path, including PMC symmetry planes. So does closed-transverse CPML, which runs under the passivity guard.
  - On the 121-scene release census, every FDTD scene's monitors are bitwise equal to the run with both controls `False`.
  - Validated on A6000 (sm_86) only. Other architectures may differ at rounding level.
  - Migration: pass `fdtd_core_path=False, accelerated_setup=False` to reproduce the 0.5.1 execution path. Use the `warnings` filters to silence or escalate `FDTDCoreFallbackWarning`. Code that inspects `prepared.solver` internals should check `execution_path` first.
- Default material sampling is `SubpixelSpec(samples=4, averaging="kottke_edge", pec="staircase")` (was one arithmetic sample). Trainable geometry requires `averaging="kottke_smooth"` (experimental) or `"polarized"`; trainable `MaterialRegion` densities require `samples=1, averaging="arithmetic"`; both fail closed otherwise. Pass `SubpixelSpec(samples=1, averaging="arithmetic", pec="staircase")` to recover 0.5.1 sampling.
- Structures that reach a PML interface and are prismatic there are continued through the PML along the face normal at preparation (FDTD and FDFD). The public `Scene` is not modified, and the extrusions are recorded as `pml_extrusions` in the prepared metadata and solver statistics. Mesh volumes, non-prismatic contacts and surface-impedance conductors (`LossyMetalMedium`, `SurfaceImpedanceMedium`, `CopperFoil`) are not extruded and warn; zero-volume sheets are only recorded. Results move only for scenes with such contacts. In the benchmark suite, 10 rows moved and none got worse; for example, `dielectric_slab` field L2 against the reference fell from 0.569 to 0.041. All other scenes are bitwise unchanged. Nonlinear structures flush with the PML now behave as infinite structures: for example, a Kerr slab's nonlinear phase shift went from 2.63e-3, an edge artefact, to 8.56e-4, which matches the infinite-slab prediction. A PEC structure and a surface-impedance conductor declared on the same face still fail closed.
- FDTD phasors use physical Yee time labels: post-step E at (n+1)Δt and H at (n+1/2)Δt.
  - Compared with 0.5.1, raw field and port phasors rotate by exp(iωΔt). Source-normalised additive-current and direct-drive phasors rotate by exp(iωΔt/2), and uncompensated magnetic, sheet and analytic-pulse phasors by exp(iωΔt). Auxiliary-line and CW references are unchanged to rounding.
  - Same-frequency S/Z/Γ, flux, matched field/port powers and directivity are unchanged.
  - Field-time monitor `t` advances by one Δt; the values are unchanged.
  - Resume checkpoints use format 6. Checkpoints with the earlier spectral convention need a fresh run.
- Additive electric currents (`PointDipole`, `UniformCurrentSource`, electric `CustomCurrentSource`) are injected at (n+1/2)Δt and normalised at their own injection instant. Raw port V/I and Z/Γ are unchanged; source-normalised spectra carry the half-step phase. Checkpoints with additive electric currents written before this change are refused on resume.
- Raw (non-source-normalised) pulsed absolute spectra are scaled per reference period instead of averaged over the record length, including single-frequency runs; with `reference_frequency=None` the period is taken per output frequency, so multi-frequency raw outputs also move off the centre frequency. Source-normalised results and all ratios (S, Z, Γ, power closure) are unchanged. Migration: absolute pulsed powers from 0.5.x differ by (f·T_record)²-type factors; compare ratios or recompute. Pass an explicit `reference_frequency` for the fixed-period convention. Absolute spectral reads that mix ongoing and transient drives without source normalisation are refused.
- Explicit `full_field_dft=False` is honoured for multi-frequency runs; volume-field reads and automatic electric power-loss channels then raise.
- Pulsed TFSF incident waves are referenced at the physical upstream entry plane, so absolute incident phase no longer depends on absorbing-layer padding. Older pulsed-TFSF checkpoints are refused on resume.
- Raw TFSF incident timing is exact on the Yee clock: auxiliary-line entry E uses the waveform at (n+1)Δt and analytic/discrete CW faces keep their physical J/M instants; normalisation references follow each provider. Migration: finite-record source-normalised TFSF values shift by up to ~1e-3 for pulses and ~1e-2 for real CW on short records; recompute affected cached results. TFSF checkpoints written before this change are refused on resume.
- The pulsed TFSF auxiliary line keeps its whole sampled extent lossless and ends in a 320-cell absorber appended beyond it. Previously its last 20 sampled cells formed a graded ramp, which reflected near-band-edge content and trapped a slowly decaying mode. In-band benchmark results agree with the old termination to 3–4 digits. Checkpoints with an auxiliary TFSF line written before this change are refused on resume.
- Complex fixed-k Bloch runs use a complex-frequency-shifted CPML by default; `cpml_config={"alpha_max": 0.0}` pins legacy coefficients for short runs. Real-field, k=0 and non-Bloch paths are unchanged.
- Fixed-k Bloch runs accept pulsed TFSF-slab plane waves (see Added). They still refuse pulsed beams, mode and custom-field sources and soft plane waves; use one CW source per frequency for those. Point and current sources may be pulsed.
- FDFD: PML now absorbs (frequency-domain form of the FDTD CPML); `PointDipole` uses the FDTD unit control-volume current moment; Yee-edge material components and exp(-iωt) loss sign are aligned with FDTD; FDFD refuses scene monitors it cannot populate and propagates solver failures.
- Other default-path numerics: high-side magnetic CPML grading at physical half points; CopperFoil free-edge impedance on by default (`edge_model="none"` for the legacy rim) and compressed passive diffusion fits; node-consistent staircase PEC; second-order multi-sample averaging on resolved Yee spacing; full-moment narrow Gaussian dipoles; periodic dipole image folding; watertight closed-surface monitors; `TwoPhotonAbsorption` conductivity factor 2/3; Yee-edge bulk conduction loss.
- Trainable fixed controls (frequencies, time/grid/sampling controls, monitor geometry, topology) and port probe gaps fully covered by PEC are rejected up front.
- Native CUDA extension ABI is `stable_abi_v13`; older prebuilt binaries are rejected and rebuilt. `WITWIN_MAXWELL_FDTD_CUDA_PREBUILT=1` now requires a matching ABI marker. The core-path extension (`core_abi_v11`) and the setup extension (`setup_abi_v6`) are compiled on first use.
- Requires `witwin>=0.4.6,<0.5`. In earlier witwin-core releases, micrometre-scale geometries were over-smoothed by about 3 cells, because the geometry smoothing width was clamped to 1.19e-7 m whatever the cell size. Optimisation results and forward fluxes change materially for µm-scale scenes (bend example: +37.7% initial flux, gradient cosine 0.85). Scenes whose smallest cell is ≥ ~2.4 µm are unchanged bit for bit. Point-like occupancy queries without coordinate spacing must now pass an explicit beta in metres (ValueError otherwise).
- `Simulation.fdtd(absorber="auto")` is the default.
  - Real-field cells with closed transverse walls (periodic, PEC or PMC) and PML on the normal axis select the graded `absorber`. It needs at least 40 layers on every PML face; thinner layers raise a `ValueError` that names the closed axes, the deficient faces and both remedies.
  - Open scenes and complex fixed-k scenes keep CPML.
  - Explicit `absorber="cpml"` in a closed-transverse real-field cell runs under a fail-closed passivity guard (`FDTDPassivityError`). In a complex fixed-k cell the guard only warns: it emits a `RuntimeWarning` and records the measured slope in `passivity_guard` metadata. Non-finite energy fails closed everywhere.
  - Results record `absorber`, `absorber_resolution_reason` and `passivity_guard`.
  - FP64 native forward resolves `"auto"` the way preparation does. It runs when `"auto"` resolves to CPML, and keeps its CPML-only refusal otherwise.
  - Closed-transverse CPML stays on the existing execution path, where the guard runs.
  - Migration: scenes that relied on the CPML default in such cells have two options. Pass `absorber="cpml"`: the numerics are unchanged and the run is now guarded. Or configure at least 40 layers: the results then come from the graded absorber.

### Fixed

- Soft equivalent-sheet plane waves launch +E_inc (absolute fields of soft plane-wave scenes previously had the wrong sign).
- Soft plane-wave and beam launch currents are no longer written into inactive electric wall rows (transverse none/PML/PEC walls), which removes a linear late-time growth of the corner H field.
- Conformal thin-sheet rims split faces only for chords inside the outline (removes a 4-7% low resonance bias).
- Custom J/M sources deposit over the Yee control-cell overlap with the declared dataset volume; custom-field sources deposit on bracketing Yee sheets with fractional aperture.
- Time modulation uses a device integer step counter with FP64 phase and an effective-medium partial-cell coefficient.
- Fixed-k Bloch: Floquet TE/TM readout with power-normalised r/t, consistent complex CW conventions with the adjoint, single deposition of periodic TFSF faces, PEC-face clamping of imaginary fields.
- Finite thin wires are stable through a passive RL impedance; long RF clocks and TEM phases use float64; lumped/terminal magnetic observers use current into the field; same-step polarization current enters direct lumped/network sampling.
- Forward source injection is run-to-run deterministic for oblique and interpolated TFSF faces, periodic and Bloch wraps, batched lanes and the core-path periodic wrap (shared cells were previously accumulated with float32 atomics, so repeated runs could differ at about 1e-6 relative). No pinned result moved; oblique TFSF scenes step about 4% slower.
- Adjoint gradients are run-to-run deterministic for TFSF auxiliary samples, collocated-monitor objectives and coincident point seeds (fixed-order gathers replace float atomics). Density and Box parameter-field material gradients are run-to-run deterministic too: their trilinear sampling uses native kernels whose forward and coordinate gradient are bitwise equal to the previous path, with an ordered texture pullback.
- Multi-GPU distributed FDTD with periodic or Bloch boundaries: a source term cropped to one GPU's owned x range kept the gather built for the uncropped patch. The injection read past the cropped data, so results depended on leftover device memory, and it routed the remaining planes one cell low. The gathers are now rebuilt after the crop. For example, a uniform current source straddling the seam between GPUs was off by 4.84 and now matches the single-device result. Distributed path only; the single-GPU default path is unaffected.
- Micrometre-scale `ModeSource`/`ModePort` launches were refused at prepare ("zero integrated Poynting power"): the zero-power check compared watts with machine epsilon. It and other absolute floors on dimensional quantities (modal power fractions, scattering/diffraction/antenna normalisation, network and port impedance normalisation, observers, TFSF power, source-term pruning, DC port-current admission) are now relative to the same-unit reference, so results do not depend on the length unit.
- Gradients through trainable material on a `ModeSource`/`ModePort` launch plane are now correct. The adjoint previously differentiated a different (scalar) mode than the one launched and lost the 1/ε injection-coefficient derivative, giving gradients wrong by up to ~7.6× (reference guide, central finite differences on each tree: before, adjoint −18334 vs FD −2417; now, adjoint −2418 vs FD −2425). Trainable lossless launch planes now differentiate via a torch dense vector eigen-solve shared by the forward launch and the adjoint replay (operator n ≤ 4096). Lossy or conductive, near-degenerate and above-cap trainable planes refuse with a named `NotImplementedError`.
- Dispersive interfaces under the `kottke_edge` default: each Yee component edge takes one constituent's complete pole set (binary ownership) for piecewise-constant pole media, including exactly uniform custom pole fields; spatially graded pole media and the gradient subpixel modes keep fractional pole weights; float32-declared box faces snap to grid planes within their declaration rounding. Replaces the fractional-ADE interface error in dispersive scatterers; sphere cross sections converge toward the analytic Mie solution under refinement.

### Performance

All timings are on an A6000 (sm_86).

- **Default core path.** 96 of the 121 release-census scenes take the core path under `"auto"`.
  - On those scenes, whole-call time (prepare and run, cold processes) fell from 670.5 s to 318.9 s (−52.4%). The run-only median speedup is 1.37×.
  - On the FDTD scenes that keep the existing path, whole-call time fell from 296.4 s to 236.6 s through accelerated setup.
  - Fused single-GPU float32 stepping has one magnetic and one electric launch per step and graph capture in 32-step chunks. It covers absorbing, PEC and periodic boundaries, generic sources and monitors, RF ports, lumped elements, wires, networks, CopperFoil, thin sheets, SIBC, and dispersive, nonlinear and modulated media.
  - On slab-CPML and no-PML cubes from 128³ to 384³, step time is within 1.025–1.107× of the Yee memory-traffic floor.
- Core TFSF auxiliary-line corrections are fused with their auxiliary updates (core ABI v11). On the 256³ TFSF row this cuts launches from 42 to 8 per step. Step time falls by 39.8% at 64³, 11.5% at 128³ and 1.9% at 256³.
- Further core-path cuts:
  - Redundant PEC clamp launches are omitted: −7.2% at 128³ and −4.2% at 256³ on PEC rows.
  - Observer gathers use one launch per batch of up to 16 groups.
  - The Yee block order is L2-aware: the 384³ slab row went from 1.148× to 1.085× of the byte floor.
  - Each auxiliary TFSF step is evaluated once during setup.
- Point-monitor setup and readout are batched, and run with cyclic garbage collection paused. On a 16,384-point sample, warm end-to-end core-path time fell from 2.95 s to 1.55 s, then by a further 25–28% with the pause.
- Accelerated setup admits float64 primitive declarations (Box, Sphere, Cylinder, Pyramid, PolySlab and boolean trees).
- Fused CopperFoil and conformal thin-sheet CUDA kernels on by default (validated against the torch reference within declared tolerances; the torch path remains the reference and adjoint path); cached, vectorised thin-wire compilation; graph-captured grouped spectral monitors.

### Limitations

Known defects are documented with magnitude, scope and workaround in the release notes; they do not block the release.

- The automatic core default and its performance figures are validated on A6000 (sm_86) only. The L2-based Yee block-order threshold is calibrated only there. Pass `fdtd_core_path=False` on other architectures if you need the existing path.
- Second-order nonlinear (chi2) media run on the core path under `"auto"` and pass their physics tests there (second-harmonic scaling and phase matching), but have no core-vs-existing equality check. Dispersive (electric and magnetic), Kerr, two-photon absorption, time modulation, their compositions and deterministic breakdown are bitwise equal to the existing path. Pass `fdtd_core_path=False` for chi2 scenes that need the qualified existing path.
- Without a CUDA toolkit (a pip install with no `nvcc`/`CUDA_HOME`), `"auto"` runs complete on the existing path with one `FDTDCoreFallbackWarning`. The first warning names the missing toolkit. Later `Simulation`s in the same process, and the recorded `fallback_reason`, instead report a missing setup-extension shared object. This is cosmetic and is fixed in 0.6.1.
- The core path does not run these, which keep the existing path under `"auto"`:
  - Bloch or complex fields;
  - PMC (including symmetry planes), Mur and mode-ABC boundaries;
  - closed-transverse CPML;
  - gyromagnetic media, full anisotropy, magnetic permeability or magnetic conductivity;
  - coordinate charts;
  - gradient-requiring scenes;
  - batch lanes, multi-GPU and non-float32 fields.
- Thin-wire port Z_in/S11 does not converge under refinement (Richardson ratio median 0.75); do not use it for quantitative results. Fix targeted for 0.6.1.
- Curved or tilted thin copper: finite-edge response low by about 4–7% (no qualified workaround; validate against a refined grid); driven conformal-sheet antennas on tilted/curved sheets follow the rim staircase (about 2% at λ/40).
- Oblique TE under fixed k: 35° transmission within 4.43% against a 3% gate with the default CFS-CPML profile; no qualified workaround (a smaller α is not passive at steep angles).
- Under fixed k, beams, mode and custom-field sources and soft plane waves are CW only. The pulsed `bloch_oblique` benchmark rows stay quarantined in this release's validation suite.
- Fixed-k TFSF reports incident phase relative to its incident-line reference; absolute phase is planned for 0.6.1.
- MoM: hierarchical and FMM configurations with `stopping.rtol` above 0.1 × `solve_dual_tolerance` raise `ValueError` (unchanged from the previous release base); set `stopping.rtol` at or below that bound.
- MoM FMM and dense-reference solves are not yet bitwise run-to-run reproducible (repeated runs differ by up to about 1e-14 relative in dense-reference currents and about 1e-10 relative in FMM currents); a tolerance-sensitive test can fail intermittently.
- Benchmark rows with a reference-convention difference also fail against the external reference: nine sign or absolute-phase rows (field L2 near 2, shape L2 ≤ 0.15), three source-gauge rows, custom_grid_slab (L2 0.120 against 0.1) and ricker_axis_x_anisotropic (reference waveform export). See the release notes.
- Ten benchmark scenarios keep an unresolved residual against the external reference solver and are reported on every run, including custom_field_source, modulated_slab(_phase) and mode_port_straight_wg (see release notes).
- Real-field periodic or closed-transverse cells can show late-time CPML growth; `absorber="auto"` therefore selects the graded absorber there (at least 40 layers), and explicit `absorber="cpml"` in these topologies runs under the passivity guard.
- The CPML passivity guard does not detect growth slower than 4e-7 per step (about 1.5× energy over 1e6 steps). Complex fixed-k (oblique Bloch) CPML can grow both inside and well above that band. Measured at 160 cells per wavelength, f0 = 1 GHz, k0 = 2π f0 / c:
  - Below the band: 2.1e-7 per step (about 1.23× per 1e6 steps) in a point-dipole εr = 4 slab cell.
  - Near the band: 3.5e-7 to 5.0e-7 per step in εr = 4 TM CW records at 1.1 f0 and at 20° incidence. 7.0e-7 to 7.5e-7 per step in the vacuum TM CW arm at k_par = 0.25 k0, 0.9 f0.
  - Slab-guided mode: 8.2e-7 per step late in a CW record of an εr = 4 TM slab at k_par = 0.25 k0, 0.9 f0. Here a slab-guided TM mode below the light line grows in the CPML.
  - About 10× larger, in vacuum TM records:
    - 7.7e-6 per step in the CW arm at k_par = 0.55 k0, 0.9 f0, late in a 136,854-step record.
    - 8.2e-6 per step in a CW record at 20° incidence, 0.9 f0, run with 600 transient cycles. The same case with 300 cycles fits 5.0e-7 per step, so the rate rises late in long CW records.
    - 7.7e-6 ± 1.9e-6 per step in an early window of a 320,000-step pulsed record at k_par = 0.55 k0.
  - The reported acceptance results are unaffected at their existing bounds: pulse/CW parity ≤ 2.5e-4, CW r/t continuity ≤ 1.2e-4, cutoff κ ≤ 8.6e-4.
  - Long fixed-k runs, especially TM runs at larger k_par, should check their energy. Prefer CW per frequency with the default transient, or short pulsed records.
  - For complex fixed-k cells the guard warns once, records the measured slope, standard error and window in `passivity_guard_warning`, and lets the run finish. It is fail-closed only for real-field closed-transverse cells; non-finite energy fails closed everywhere.
- The passivity guard does not run on closed-transverse CPML scenes that contain CopperFoil or thin sheets.
  - These scenes report `passivity_guard = "skipped: energy storage not counted (CopperFoil, thin sheets)"` and warn.
  - Sampling their counted energy every 32 steps costs 39–133% of a step, and sparser sampling false-trips.
  - Counting is planned for 0.6.1. See `docs/reference/fdtd-cpml.md`.
  - Scenes with dispersive (ADE) or gyromagnetic media, lumped networks, SIBC, thin wires or coaxial elements are also skipped with a `RuntimeWarning`.
- Conformal PEC (`pec="conformal"`) keeps a curved-body bias and warns at construction; `kottke_edge` is not geometry-differentiable.
- Resolved volumetric conductors at 2–4 cells per skin depth under the default `kottke_edge` material policy show ±4–8% non-monotone tier sensitivity in absorbed power; use SIBC (`LossyMetalMedium`) for good conductors.

- Tidy3D export for nonuniform grids, mixed boundaries, expanded geometry, material, source, and monitor families.
- CUDA graph capture coverage for standard, Bloch, dispersive, nonlinear, and TFSF stepping paths.
- Native CUDA SIBC updates, full-anisotropic conductive-current capture, and a device-resident modulation clock, all compatible with CUDA Graph replay.
- Python 3.10-3.14 and PyTorch 2.10-2.12 validation for the packaged LibTorch Stable ABI CUDA extension.

### Changed

- Consolidated the public architecture around the declarative `Scene -> Simulation -> Result` workflow. FDTD is the primary full-featured runtime; FDFD uses the same public model but remains a limited/experimental CUDA-only single-frequency path.
- Moved FDTD adjoint hot paths from Python/Torch replay to native CUDA kernels while keeping PyTorch autograd as the public differentiation interface.
- Generalized automatic/custom nonuniform grids, subpixel averaging, conformal PEC placement, and source phase correction to use local physical grid spacing.
- Standardized physical-domain handling so PML cells are appended outside `Domain.bounds`; material/source/monitor validation and cross-solver comparisons use the unchanged physical bounds.
- Adopted the WiTwin dual-license model and release wheels with CUDA 12.8 fat binaries for Linux and Windows.

### Fixed

- Aligned Maxwell and Tidy3D plane-wave and TFSF amplitudes using their physical power/field definitions instead of fitted dimensionless factors.
- Converted explicit Bloch vectors from Maxwell radians/metre to Tidy3D's dimensionless `k * period / (2*pi)` convention.
- Preserved requested field-monitor components during Tidy3D export and validation-cache loading, preventing undeclared near-zero components from being selected as scalar observables.
- Corrected external-PML SIBC half-space detection and low-side Yee surface-node placement for `LossyMetalMedium`.
- Corrected Gaussian-pulse phase/reference handling, CW export ramp bandwidth, source-spectrum normalization, flux-aperture integration, and coordinate-aligned complex-field comparison.
- Replaced invalid validation scenarios with physically supported TFSF, diffraction-monitor, cavity-probe, and closed-surface near-to-far workflows.
- Added visual slice/phase diagnostics and solver-independent scalar comparisons for resonances, diffraction orders, directivity/beamwidth, RCS, and S-parameters.
- Corrected symmetry-face PML removal, high-face grid anchoring, and Yee-control-volume point-dipole image scaling.
- Corrected singleton custom-current datasets on staggered Yee components so magnetic current samples compile to the nearest component location.
- Kept the stable-ABI CUDA extension source portable across MSVC and Linux NVCC by using explicit typed input tables in native anisotropic-current validation.
