# Automatic directional regional planner contract

Use `AutomaticDirectionalRegionPlan(basis, medium, geometry=prepared, kernel_error_budget=..., ideal_rwg_error_budget=B, balancing_impedance=eta_ext)` for a complete fixed CUDA float64 region. For the exterior, pass the actual `ScalarSystemBlocks` provider as basis, its exact exterior medium, and no separate geometry. The shared actual support tree and partition are generated automatically. Local body geometry remains caller-owned; the global provider owns its prepared body geometry.

The plan owns its support tree, centers/radii, canonical carrier catalog and per-FAR cone/order plans, including their generated declared inputs. `receipt()` reports exact native tensor inventory and separate component workspace allowances. Pair and carrier/order family limits are explicit; at most32 canonical families are supported by the current fixed-carrier forest. There is no universal frequency/mesh admission guarantee. Failures never silently become a different partition or a relaxed tolerance.

`plan.build_region(integration=config, quadrature_order=q, ...)` returns the existing `DirectionalRegionalOperator` with original packed D/K near and actual-medium sparse FAR. Supply the exact original provider integration object for a global exterior. The selected polynomial order determines the minimum permitted q; polynomial exactness is not a quadrature convergence certificate. Projection, cumulative table and near retained budgets are separate components; there is no whole peak guarantee. Complete all-near plans allocate an empty zero-byte sparse forest and all physical entries are original near blocks.

The regional ideal bound uses physical-disjoint RSS, each pair B/sqrt(F), conservatively split G/grad squares and actual material/RWG weights. It excludes numerical moments/shifts, finite phase arithmetic, quadrature, solve error and physical reference error. Compose admitted exterior and disjoint interior regions with `DirectionalSystemActions` and its unchanged common-impedance triangle/RSS and original provider/body identity checks. Apply and adjoint remain native PyTorch current actions.

Every plan receipt/build refuses changes to native arrays or autograd modes, partition/catalog policy, actual material physical values, tree metadata and caller geometry. Numerical owners retain their own unchanged source/receiver/medium/near and saved-backward state guards. Plan arrays are fixed configuration, not differentiable geometry/material variables.

The stage evidence is `docs/assessments/sie_directional_automatic_region.json` and `/tmp/gsp-directional-automatic-region-evidence-v1/summary.json`. No physical, production, native-error, whole-resource or complexity qualification follows. All original Goal acceptance requirements remain active.
