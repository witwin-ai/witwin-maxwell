# Deterministic native adjoint accumulation

The native float32 adjoint no longer uses floating-point atomics for collocation, TFSF auxiliary samples or point-monitor seeds. The source-deposition kernels and core step are untouched. Private operator schemas require stable ABI v10 (v9 added the forward source gathers); stale binaries must rebuild.

- Collocation launches one target-component grid at a time, with one thread per Yee edge. It gathers source components Ex, Ey, Ez in that order, candidate source cells in ascending C order, and matching stencil corners in their original four-corner order. Clamped duplicate corners are added individually, using explicit float32 multiply/add rounding for `2*own*g` and `0.5*collocated*g`. There is no plan allocation and no competing writer.
- TFSF builds device CSR rows once before the reverse loop. Each auxiliary sample row stores contributing flattened patch-cell indices in ascending order and float32 interpolation weights (lower before upper when sorting). Scalar, line, duplicate line-index and interpolated terms share one kernel. A thread accumulates its row serially, starting from the existing sample adjoint; term launches keep the forward term order on the current stream. No floating-point atomic or schedule-dependent reduction tree remains.
- Point seeds build device CSR rows per unique flattened Yee cell at seed preparation. Stable sorting preserves ascending original point order. One thread reduces points in that order and frequency entries in ascending order, rounding each point to field dtype before adding to the existing field adjoint. FP32 and FP64 observer cotangents both use this path; the FP64 observer's former indexed-add path is removed.

Plans use device-native sorting and integer counts, with no field transfer to CPU and no plan building per reverse step. GPU integer counts cannot change the resulting offsets with execution order. Density interpolation backward has its own atomic accumulation outside this work and remains outside the bitwise guarantee.

Standalone nonlinear MNA in `compiler/nonlinear_devices.py` uses `index_put_(accumulate=True)` for both conductance stamps and current scatters: its CUDA implementation sorts indices and then accumulates, rather than using floating-point atomics. Coordinator-provided verification on torch `2.13.0+cu130` with `torch.are_deterministic_algorithms_enabled()` returning `False` found one distinct result over 3,000 runs with 43 duplicate contributions. CUDA `index_add_` uses atomics and is only empirically ordered. Regression tests cover three fresh CUDA builds of the full-wave and three-diode shared-node transients, plus 200 duplicate-stamp repeats on nonzero bases in float32 and float64; CPU rectifier trajectories remain bitwise unchanged.

Possible expectation changes and the complete comparison census are in [the assertion audit](../assessments/deterministic-adjoint-expectations.md). Existing exact replay/repeatability gates must still pass; no pin or tolerance was changed. All seven historical BITID files cover forward behavior and are expected unchanged. The branch-keyed integration declaration records conservative gradient gate files.

CPU validation: offline sm_86 full extension build/load; CPU extraction of the actual gather implementation equals the original scatter in a fixed source/cell order bit-for-bit over 125 grids and 18,000 edges, including singleton axes and clamped corners; CPU gradient/plan suites: 79 passed, 361 GPU skips. Manifest, ABI, toolkit-discovery and FP64 observer contract checks: 59 passed.
